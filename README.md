# PersonalFinancePlan

Система для построения персонального финансового плана: учёт транзакций
(доходов и расходов), цели накоплений, месячные бюджеты по категориям,
«Купийка» – общий план расходов
с другими людьми в реальном времени, аутентификация пользователей и
клиентское React-приложение. Курсовой проект, выполняется поэтапно в рамках
лабораторных работ.

## Структура репозитория

- Корень репозитория – серверная часть (REST API, Express + PostgreSQL,
  Socket.IO).
- `routes/`, `controllers/`, `models/`, `middleware/` – слои REST API.
- `validators/` – схемы валидации тела запросов (Joi), подключаются в
  маршрутах через `middleware/validate.js` (Практическое занятие 2).
- `docs/openapi.yaml` – спецификация OpenAPI для Swagger UI, `API.md` –
  описание всех эндпоинтов (Практическое занятие 2).
- `socket/` – обработчики событий Socket.IO (Лабораторная работа 7).
- `client/` – клиентское React-приложение, работает с REST API сервера
  через axios (Лабораторная работа 5) и с Socket.IO через socket.io-client
  (Лабораторная работа 7).

## Сервер

### Стек

- Node.js, Express.js
- PostgreSQL, Sequelize (миграции, сиды, связи моделей)
- JWT (jsonwebtoken), bcrypt – аутентификация
- Joi – валидация входных данных
- swagger-jsdoc, swagger-ui-express – документация API (Swagger UI)
- cors – разрешение запросов от клиента (http://localhost:5173)
- Socket.IO – обмен событиями в реальном времени (WebSocket с запасным
  long polling) на том же порту, что и REST API

### Установка и запуск

Требуется установленный Node.js и локальный PostgreSQL.

    npm install

Создать файл `.env` в корне репозитория:

    DATABASE_URL=postgres://<user>:<password>@localhost:5432/finance_plan
    JWT_SECRET=<секретная строка>

Применить миграции:

    npm run db:migrate

Запустить сервер:

    npm run dev

Сервер запустится на http://localhost:3000
`npm run dev` – запуск с автоперезапуском (nodemon); `npm start` – обычный запуск.

Тестовые данные привязываются к пользователю, поэтому сначала нужен
подтверждённый пользователь: зарегистрироваться (`POST /auth/register`) и
открыть ссылку подтверждения, которую сервер выводит в консоль. Затем:

    npm run db:seed

Сид добавляет демо-транзакции первому подтверждённому пользователю. Демо-цели
накоплений для конкретного пользователя:

    npm run goals:seed -- <email>

### Документация API

- Swagger UI: http://localhost:3000/api-docs – описание всех эндпоинтов,
  схемы данных и кнопка «Try it out» для запросов прямо из браузера (токен –
  через «Authorize»). Спецификация – `docs/openapi.yaml`; после её изменения
  сервер нужно перезапустить.
- `API.md` – то же описание в виде документа: таблицы эндпоинтов, примеры
  запросов и ответов, коды ошибок.

### Общие правила API

- Все маршруты, кроме `/auth/*`, требуют заголовок
  `Authorization: Bearer <токен>`. Транзакции, цели и бюджеты привязаны к
  пользователю: каждый видит и меняет только свои записи, чужая запись –
  404.
- У каждого ресурса полный набор операций: GET (список и по id), POST
  (201 + заголовок `Location`), PUT (полная замена), PATCH (частичное
  обновление), DELETE (204).
- Тело запроса проверяется до контроллера (Joi): обязательные поля, типы
  (строка `"100"` вместо числа не принимается), форматы дат, лишние поля
  запрещены. Ошибка – 400 в едином формате
  `{ "error": "текст", "details": [{ "field", "message" }] }`.

### Эндпоинты

**Транзакции** (требуют заголовок `Authorization: Bearer <токен>`)

| Метод  | Путь              | Назначение                         |
| ------ | ----------------- | ----------------------------------- |
| GET    | /transactions     | список своих транзакций            |
| GET    | /transactions/:id | одна транзакция по id              |
| POST   | /transactions     | создать транзакцию                 |
| PUT    | /transactions/:id | полностью заменить транзакцию      |
| PATCH  | /transactions/:id | изменить только переданные поля    |
| DELETE | /transactions/:id | удалить транзакцию                 |

Фильтрация списка: `GET /transactions?type=income|expense` и/или `?category=<строка>`

Поиск: `GET /transactions?search=<строка>` – подстрока в категории или
описании без учёта регистра.

Поля транзакции: `amount` (число > 0, до 2 знаков после запятой), `type`
(income/expense), `category` (строка), `date` (ГГГГ-ММ-ДД, по умолчанию –
текущая дата), `description` (строка, необязательно), `isRecurring` (bool,
необязательно).

**Аутентификация**

| Метод | Путь                     | Назначение                          |
| ----- | ------------------------ | ------------------------------------ |
| POST  | /auth/register           | регистрация пользователя             |
| POST  | /auth/login               | вход, выдаёт JWT                    |
| GET   | /auth/verify-email/:token | подтверждение email                 |
| GET   | /profile                  | профиль текущего пользователя (JWT) |

**Цели накоплений** (требуют заголовок `Authorization: Bearer <токен>`;
пользователь видит и меняет только свои цели)

Хранятся в таблицах `Goals` и `GoalContributions` (связь «один ко многим»,
взносы удаляются вместе с целью).

| Метод  | Путь                                     | Назначение                               |
| ------ | ---------------------------------------- | ---------------------------------------- |
| GET    | /goals                                   | список целей                             |
| GET    | /goals/stats                             | сумма взносов по месяцам                 |
| GET    | /goals/:id                               | одна цель                                |
| POST   | /goals                                   | создать цель                             |
| PUT    | /goals/:id                               | полностью заменить цель                  |
| PATCH  | /goals/:id                               | изменить только переданные поля          |
| DELETE | /goals/:id                               | удалить цель вместе со взносами          |
| POST   | /goals/:id/contributions                 | добавить взнос                           |
| PATCH  | /goals/:id/contributions/:contributionId | изменить взнос                           |
| DELETE | /goals/:id/contributions/:contributionId | удалить взнос                            |
| POST   | /goals/:id/tags                          | добавить тег (`{ "tag": "..." }`)        |
| DELETE | /goals/:id/tags/:tag                     | убрать тег                               |

Параметры списка: `?tag=<тег>`, `?search=<строка>` (подстрока в названии без
учёта регистра), `?status=active|reached`, `?page=<номер>&limit=<1–50>`.
Ответ списка: `{ goals, total, page, limit }`.

Поля цели: `title` (строка, до 100 символов), `targetAmount` (число ≥ 1),
`deadline` (ГГГГ-ММ-ДД, необязательно), `tags` (массив строк, необязательно).
Поля взноса: `amount` (число > 0), `date` (ГГГГ-ММ-ДД, по умолчанию –
текущая дата), `note` (строка, до 200 символов, необязательно). В ответе
у цели есть вычисляемые поля `savedAmount`, `progress` (%) и `status`.

**Бюджеты** (требуют заголовок `Authorization: Bearer <токен>`;
Практическое занятие 2)

Месячный лимит расходов по категории, таблица `Budgets`. У пользователя
один бюджет на пару «категория + месяц» – повтор даёт 409 Conflict.

| Метод  | Путь         | Назначение                      |
| ------ | ------------ | -------------------------------- |
| GET    | /budgets     | список своих бюджетов           |
| GET    | /budgets/:id | один бюджет                     |
| POST   | /budgets     | создать бюджет                  |
| PUT    | /budgets/:id | полностью заменить бюджет       |
| PATCH  | /budgets/:id | изменить только переданные поля |
| DELETE | /budgets/:id | удалить бюджет                  |

Параметры списка: `?month=ГГГГ-ММ`, `?category=<строка>`.
Поля бюджета: `category` (строка, до 100 символов), `limitAmount`
(число > 0), `month` (ГГГГ-ММ).

## Купийка (Socket.IO, Лабораторная работа 7)

Общий план расходов для семьи, друзей или коллег. Пользователь создаёт
купийку и получает код приглашения, другие вступают по коду. Участники
добавляют статьи расходов, отмечают, кто что оплатил, видят разделение
расходов (доля каждого, переплата или долг), пишут в ленту купийки и
получают уведомления – всё в реальном времени, без перезагрузки страницы.

Данные хранятся в PostgreSQL: `SharedPlans`, `PlanMembers`, `PlanItems`,
`PlanMessages` (история ленты, при открытии купийки приходят последние 50
записей).

Подключение: `io("http://localhost:3000", { auth: { token } })` – токен
проверяется при подключении (`io.use`), без него соединение отклоняется
(`connect_error: Unauthorized`). Каждый сокет состоит в группе своего
пользователя `user:<id>` и в группах своих купиек `plan:<id>`.

Действия клиента отправляются с подтверждением (acknowledgement): ответ
`{ ok: true, ... }` или `{ error: "..." }`.

| Событие клиента | Данные                       | Что делает                               |
| --------------- | ---------------------------- | ---------------------------------------- |
| `plans:list`    | –                            | мои купийки                              |
| `plan:create`   | `{ title }`                  | создать купийку, выдать код приглашения  |
| `plan:join`     | `{ code }`                   | вступить по коду                         |
| `plan:open`     | `{ planId }`                 | участники (кто в сети), статьи, история  |
| `item:add`      | `{ planId, title, amount }`  | добавить статью                          |
| `item:pay`      | `{ planId, itemId }`         | «я оплатил(а)» / снять отметку           |
| `item:remove`   | `{ planId, itemId }`         | удалить статью (автор или создатель)     |
| `chat message`  | `{ planId, text }`           | сообщение в ленту (до 500 символов)      |
| `typing`        | `{ planId }`                 | «печатает…» (без подтверждения)          |
| `remind`        | `{ planId, userId }`         | личное напоминание участнику             |

| Событие сервера       | Кому                                   |
| --------------------- | -------------------------------------- |
| `plan:updated`        | всем участникам купийки (`io.to`)      |
| `chat message`        | всем участникам купийки                |
| `member joined`       | участникам, кроме вступившего          |
| `user online/offline` | участникам общих купиек, кроме самого  |
| `user typing`         | участникам, кроме печатающего          |
| `reminder`            | только адресату (группа `user:<id>`)   |

Проверка: запустить сервер и клиент, открыть два окна с разными
пользователями (например, обычное окно и окно инкогнито), создать купийку
в одном и вступить по коду в другом.

## Клиент (`client/`)

React-приложение на Vite. Вход по email и паролю, список транзакций
загружается с сервера, добавление, редактирование и удаление отражаются
в интерфейсе после подтверждения сервером (пессимистичное обновление).
Поиск по транзакциям выполняется на сервере с задержкой (debounce) ввода.
Раздел «Купийка» работает через Socket.IO (socket.io-client), в шапке
показан статус соединения.

Перед запуском сервер должен быть запущен (см. выше).

    cd client
    npm install

Создать файл `client/.env` по образцу `client/.env.example`:

    VITE_API_URL=http://localhost:3000

Запустить клиент:

    npm run dev

Откроется на http://localhost:5173. Для входа нужен пользователь с
подтверждённым email (регистрация – `POST /auth/register`, ссылка
подтверждения выводится в консоль сервера; примеры запросов – в
`requests.http`).
